* Review of existing AW2 reverse-engineering references

Reviewed the following source snapshots on 2026-10-22. These projects are
research leads only; neither is a verified Python state-decoding interface.
Keep every source-derived structure or address as a candidate until it is
checked against the supported, unmodified US retail ROM with controlled
observations.

** Eebit/aw2bhr decompilation

- Snapshot: commit =63a26942a9a1249fe4e02c4c2ec0b3d2ee6b16cb=.
- Scope: this snapshot has a small amount of decompiled C alongside assembly
  and data. [[https://github.com/Eebit/aw2bhr/blob/63a26942a9a1249fe4e02c4c2ec0b3d2ee6b16cb/src/title-screen.c][=src/title-screen.c=]] is a lead for title-screen and title-to-menu

* Capture a memory dump

Start a research session as described in [[file:MILESTONE-2.org][Milestone 2]], then run the
following in another terminal with the same project environment. The command
connects to the running loopback bridge on port 43128; it does not launch mGBA.
Use the same local ROM file as the running emulator.

#+begin_src sh
aw2-lab dump-memory --rom /path/outside/repo/aw2.gba \
  --range 0x02000000:0x100 --range 0x03000000:64 \
  --output /path/outside/repo/aw2-research/dumps/before-move.json \
  --emulator-mode headless \
  --emulator-build 'mGBA fd9dc5c2cbf234365068855851107e762fc6211b with repository frame-gate patch' \
  --checkpoint 'battle-start checkpoint; restored before observation' \
  --reproduction 'Restore battle-start; advance 1 neutral frame; no further inputs'
#+end_src

=--rom= defaults to =AW2_ROM_PATH=. Each repeatable =--range ADDRESS:LENGTH=
accepts decimal or hexadecimal integers. A capture supports 1–64 ranges and at
most 4096 bytes combined; larger requests are rejected rather than split.
Ranges retain their requested order, including overlaps and empty ranges. All
bytes and the reported frame come from one paused bridge request. Capturing
neither advances frames nor changes the held keys.

Schema version 1 JSON contains =schema_version=, UTC =captured_at=,
=tool_version=, =rom_profile= (including SHA-256 and layout/decoder versions),
operator-supplied =context=, =frame=, and ordered =ranges=. Each range contains
an integer =address=, =length= in bytes, and =bytes_hex=; decode the latter with
Python's =bytes.fromhex()=. The context records =emulator_mode=,
=emulator_build=, =checkpoint=, and =reproduction=. Supply an explicit starting
state such as "initial boot, no checkpoint" when no checkpoint was restored.

The supplied ROM file is checksum-verified. Its association with the running
emulator, the frontend, build identity, checkpoint, and reproduction steps are
operator assertions; the bridge does not independently attest them. Keep other
research clients idle while recording reproduction context. Use a fresh output
filename: existing files are never overwritten. The destination directory must
already exist; write failures remove partial output. Keep dumps outside the
repository and Nix store. This tool has ROM-independent checks; actual frontend
parity remains covered by the optional emulator integration checks.

* Compare memory dumps

Capture one dump immediately before a controlled gameplay event and another
immediately after it. Keep the ROM and requested ranges the same, and record
the event in each dump's reproduction context. Then compare the artifacts
offline:

#+begin_src sh
aw2-lab diff-memory \
  /path/outside/repo/aw2-research/dumps/before-capture.json \
  /path/outside/repo/aw2-research/dumps/after-capture.json
#+end_src

The command checks that both files use schema version 1, have the same ROM
profile, and contain identical ranges in the same order. It prints the frames
and checkpoint/reproduction context, followed by each changed byte's address,
before and after values, and range. No output file is created. A comparison
with no changed bytes reports a zero count. Use these changes as candidates for
further investigation; a byte change alone does not establish field meaning.

* Watch memory across frame steps

Use =watch-memory= to sample an initial state, advance explicitly requested
neutral frames, and record one coherent sample after each step:

#+begin_src sh
aw2-lab watch-memory --rom /path/outside/repo/aw2.gba \
  --range 0x02000000:0x100 --range 0x03000000:64 \
  --steps 10 --frames-per-step 1 \
  --output /path/outside/repo/aw2-research/dumps/property-capture-watch.json \
  --emulator-mode headless \
  --emulator-build 'pinned mGBA build with repository frame-gate patch' \
  --checkpoint 'battle-start checkpoint' \
  --reproduction 'Restore battle-start; observe 10 neutral frames'
#+end_src

Each sample records its emulator frame and the bytes for every requested range.
The log also records every byte change between consecutive samples with the
resulting frame and address. The command prints a readable summary and writes a
schema version 1 JSON artifact. It takes 1–600 steps of 1–600 neutral frames
each, with the same 64-range and 4096-byte limits as a memory dump. It captures
once before stepping and once after each step. Reads do not advance frames; only
the requested neutral frame steps do. The ROM profile is checksum-verified, but
the operator remains responsible for ensuring the running emulator matches the
supplied ROM and context. Existing output files are never overwritten.
