   - [X] Identify unit table layout, bounds, occupancy, and slot reuse.

     the allocator uses slots 1..50 in each block. A zero type byte marks an
     unused record, and two red-block sequences support lowest-empty-slot
     allocation and reuse. See [[file:AW2-STATE-VALIDATION.org::*Units and cargo][the bounded unit checks]] and

   - [X] Decode type, owner, position, and raw/displayed health.
     Byte +0 is the type ID; owner is implied by the army block; bytes +2/+3
     are X/Y; byte +4's low seven bits hold internal health. A controlled move,
     four-player roster, combat samples, and displayed-4-HP Infantry checkpoint
     support these interpretations. Ammo occupies bits 7..10 of the same
     halfword at +4. Exact HUD rounding for every health value remains open. See

   - [X] Decode fuel, ammo, and action status.
     Fuel is byte +6 bits 0..6; the HUD reader masks away bit 7, which Join

     bits 1/2 control visible/logical lookup handling, and bits 3/4 mark an

     meanings do not alone establish command readiness. See the status-bit
     trace above; no complete typed unit decoder is introduced here.
