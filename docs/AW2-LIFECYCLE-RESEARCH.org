** Verified structures and bounded screen associations
All multi-byte values below are unsigned little-endian integers. Match this
exact ROM profile before using any addresses or script identifiers.

| Address/rule | Interpretation | Type and bounds | Corroboration |
|--------------+----------------+-----------------+---------------|
| =LE32(0x0801CB38)= | Screen-process pool base, =0x0200D610= | ROM literal =u32 LE= | Original search routine =0x0801CB28= |
| =0x0200D610 + 0x6C*n= | Process script identifier | =u32 LE=, n=0..31, zero means no script | Original search advances 0x6C and bounds index at 0x1F |
| =0x030040D0= | Engine callback A | =u32 LE=, Thumb function pointer | Setter =0x080366D0=, getter =0x080366E8= |
| =0x030040EC= | Engine callback B | =u32 LE=, Thumb function pointer | Setter =0x080366C4=, getter =0x080366DC= |

Read the 32-slot pool as a bounded 3,456-byte region. Check each slot's first
word; do not infer activity from leftover callbacks or payload bytes in a slot
whose script word is zero. Match known script values; unrecognized values have
no lifecycle meaning established here. Pool absence is not a positive battle
signal. No linked-list traversal or unbounded pointer following is needed for
these presence checks.

|------------------------+-----------------------------------+-------|
| Startup logo | =0x08581500= | State 1 and neutral controls |
| Title / Press Start | =0x08581C68= | State 2 and neutral controls |
| Select Mode | =0x0849E818= | Both Campaign and Versus highlights |
| Versus map selection | =0x08616C54= | State 5 and return from setup |

The two callback pairs, preserving their Thumb low bits, are:
- Screen engine: =(0x08036885, 0x080368E9)= in all seven non-battle source states.
- Battle engine: =(0x08036945, 0x080369BD)= in the active-battle source state,
  the battle-entry fade, turn-start sequence, battle menu, and save prompt.

Original =0x0803662C= installs the battle pair; =0x080366A4= installs the screen
pair through the setters above. This verifies engine selection, not battle/UI
  phase or input availability. Never execute or dereference these values as host pointers.

Every supplied state was sampled at restore, after 10 neutral frames, and after
60 total neutral frames. Callback pairs and the associated screen script remain
consistent in all 24 observations. Campaign and Versus highlights share the
same parent process; Teams and Rules also share their parent. A finer phase
decoder needs additional verified child state. The byte at =0x02017C76= is 0
in Teams and 2 in Rules, but remains 2 in battle; it is only a candidate setup
subphase lead, with no standalone validity interpretation.

** Decoder implications and unresolved work
- Reject battle decoding in recognized title/mode/map-selection/setup contexts.
  The screen-engine pair is a conservative exclusion signal for the observed
  Versus path. Unknown or conflicting signals must remain unknown.
- A matching battle-engine pair supports an engine-family observation. Classify
  battle entry, power activation, and known result sequences separately; it is
  not an unconditional ongoing-battle or command-availability flag. Validate
  individual fields in their observed phases. An animation does not by itself
  invalidate already initialized map data or introduce another confirmation.
- Keep map-data validity, lifecycle phase, and whether the UI accepts commands
  separate. These observations demonstrate that their transitions need not
  coincide, without establishing their complete validity intervals.
- Victory/defeat, post-result prompts, and retained map/day/property data after
  returning to menus were missing from this initial run. The later result finding
  supplies those observations for the tested two-army paths.
- Later coverage verifies the tested Versus resume paths, three CPU turns,
  combat including disabled/skipped animations, regular/Super Power, save/yield
  dialogues, and headless/windowed parity. These results narrow the open work:
  Campaign event flows, other CO-specific and AI/combat variants, additional
  setup/menu contexts, and universal outcome rules remain unverified. The title
  timer can enter other behavior; the neutral startup controls cover only the
  first 60 frames after each source state.

** Conservative runtime classifier
The implementation is in =src/aw2_lab/lifecycle.py=. It accepts the two callback
words, script IDs read from the bounded process pool, and optional battle-control
fields. It returns a phase, engine family, matching scripts, and a battle-decode
safety status. All fields must come from one coherent snapshot; zero script
words are ignored.

- Exact screen and battle callback pairs identify the engine family only;
  Thumb low bits are significant.
- Known startup, title, mode-selection, Versus map-selection, and Versus setup
  processes classify the observed front-end phases. The shared setup parent
  cannot distinguish Teams from Rules. Results take precedence over retained
  battle callbacks and stale battle data.
- Known transition processes classify as =BATTLE_TRANSITION= with either
  observed callback pair. These effects also occur during ordinary turn changes;
  their presence alone cannot identify the beginning of a match. Earlier replay
  tables below retain the former =BATTLE_ENTRY= label used when collected.
- Optional =BattleControlObservation= fields identify the tested human map-input
  mode as =BATTLE_PLAYER_TURN=. The battle callback pair, controller mode 1,
  state 13, zero controller lock/input gate, input state 0, and no active screen
  scripts must all agree. Without these controls, process-free states remain
  =BATTLE_ENGINE_UNRESOLVED=. See [[*Finding: battle-controller state and human player turns][the controller finding]] for evidence and limits.
- A simultaneous victory and defeat presentation signal is treated as
  conflicting evidence and classified =UNKNOWN=.
- =BattleDecodeSafety.BLOCKED= means do not interpret data as a live active
  battle; =UNKNOWN= means the classifier cannot establish safety. The
  classifier alone never authorizes decoding. The separate structure validator
  permits the researched subset only when lifecycle classification identifies
  a human player turn and geometry, properties, players, and units all pass.
  This positive gate is verified only in the tested Versus contexts; Campaign
  flows, additional busy states, and unrecognized contexts remain blocked or
  unresolved.

This is a conservative exclusion/classification aid, not a complete lifecycle
decoder. The tested Versus resume, AI, combat, powers/dialogues, results, and
windowed-parity paths are documented in [[file:AW2-LIFECYCLE-COVERAGE.org][lifecycle coverage]]. Campaign
event flows, additional combat/CO variants, other setup/menu contexts, and
universal outcome rules remain open. Preserve the distinction between phase
classification and per-field validity: some battle data is initialized during
entry and retained after results and menu return.
The companion [[file:AW2-STATE-VALIDATION.org][structure validator]] now supplies separate bounded consistency
checks and a live-field availability decision; the classifier alone still does
not authorize decoding.
