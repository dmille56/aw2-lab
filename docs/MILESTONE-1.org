   - Decision: the pinned headless and windowed builds require the opt-in
     =mgba-frame-gate.patch=. The selected unpatched executables opened the bridge
     listener but did not invoke =bridgePoll=, so requests stalled and exact frame
     control was unavailable. With the patch, the frame-gate integration checks
     passed in both modes, verifying idle responsiveness, observations that do not
     advance emulation, and exact frame budgets. See the Emulator bridge section in
     [[file:PLAN.md]].

     budget after its callback returns. The Qt frontend also blocks UI unpause/step
     and local gameplay input while the gate is enabled.
